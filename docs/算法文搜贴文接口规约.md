# 算法侧文搜贴文接口规约

> 面向 T1/T2/T3 等算法服务调用。该接口由课题四后端提供，用于根据自然语言 query 召回 `media_contents` 贴文及其相关多媒体命中证据。

---

## 1. 接口概览

| 项目 | 说明 |
|---|---|
| 接口名称 | 文搜贴文接口 |
| HTTP Method | `POST` |
| Path | `/api/search/media-contents` |
| 线上示例地址 | `http://172.16.40.232:5555/api/search/media-contents` |
| Content-Type | `application/json` |
| 鉴权 | 当前已加入后端白名单，算法服务调用不需要 JWT |
| 返回格式 | 后端统一 `Result<T>` 包装：`success/code/message/data` |

兼容说明：旧路径 `POST /api/algorithm/media-contents/search` 暂时保留，内部调用同一套实现。新接入请统一使用 `/api/search/media-contents`。

---

## 2. 能力范围

接口底层复用后端已有混合检索链路，支持：

1. **关键词检索**：ES BM25，检索贴文 `title/body_text/summary/translated_*` 字段。
2. **语义检索**：Milvus 向量检索，检索贴文标题、摘要、正文向量。
3. **跨语种检索**：使用 query translation 扩展查询，并检索翻译字段和 pivot embedding。
4. **多媒体资源检索**：检索媒体资源 OCR、ASR、caption、translated OCR/ASR/caption 及媒体语义向量。
5. **融合排序**：使用 RRF 融合文本关键词、文本语义、媒体关键词、媒体语义等通道。
6. **基础过滤**：支持平台、语言、内容类型、作者平台 ID、发布时间范围过滤。

## 3. 请求体

```json
{
  "query": "taiwan military defense",
  "platform": "reddit",
  "language": "en",
  "contentType": "post",
  "authorPlatformUserId": "author_123",
  "publishedFrom": "2026-07-01T00:00:00+08:00",
  "publishedTo": "2026-07-27T23:59:59+08:00",
  "topK": 20,
  "enableKeyword": true,
  "enableSemantic": true,
  "enableMedia": true,
  "enableGraph": false,
  "targetModalities": "all",
  "semanticMinScore": 0.45,
  "visualMinScore": 0.65
}
```

### 3.1 字段说明

| 字段 | 类型 | 必填 | 默认值 | 说明 |
|---|---:|---:|---:|---|
| `query` | string | 是 | - | 检索 query，支持中文、英文或混合表达。 |
| `platform` | string | 否 | 不过滤 | 平台过滤，如 `reddit`、`x`、`telegram`、`youtube`、`news`。 |
| `language` | string | 否 | 不过滤 | 语言过滤，如 `en`、`zh`。注意：填了语言会限制结果语言。 |
| `contentType` | string | 否 | 不过滤 | 内容类型过滤，如 `post`、`comment`、`reply`、`quote`、`repost`、`article`。 |
| `authorPlatformUserId` | string | 否 | 不过滤 | 作者平台原始用户 ID。 |
| `publishedFrom` | string | 否 | 不过滤 | 发布时间起始，ISO-8601，例如 `2026-07-01T00:00:00+08:00`。 |
| `publishedTo` | string | 否 | 不过滤 | 发布时间结束，ISO-8601。 |
| `topK` | integer | 否 | 20 | 最终返回条数，上限受后端 `MAX_RECALL_SIZE` 保护。 |
| `size` | integer | 否 | - | `topK` 的兼容别名；同时传时优先使用 `topK`。 |
| `enableKeyword` | boolean | 否 | true | 是否启用 ES 关键词检索。 |
| `enableSemantic` | boolean | 否 | true | 是否启用 Milvus 语义检索。 |
| `enableMedia` | boolean | 否 | true | 是否召回多媒体资源命中，如 OCR/ASR/caption。 |
| `enableGraph` | boolean | 否 | false | 是否启用 Neo4j 内容节点召回；默认关闭。 |
| `targetModalities` | string | 否 | `all` | 媒体检索范围；常用值：`all`、`text`、`image`、`video`、`audio`。`enableMedia=false` 时后端按 `text` 处理。 |
| `semanticMinScore` | number | 否 | 后端默认阈值 | 文本语义召回最小分数；一般不建议算法侧强行传。 |
| `visualMinScore` | number | 否 | 后端默认阈值 | 视觉/媒体召回最小分数；一般不建议算法侧强行传。 |

### 3.2 推荐调用方式

普通文本问题：

```json
{
  "query": "南海 军事演习",
  "topK": 20,
  "enableKeyword": true,
  "enableSemantic": true,
  "enableMedia": true
}
```

只搜英文 reddit 贴文：

```json
{
  "query": "taiwan blockade military exercise",
  "platform": "reddit",
  "language": "en",
  "topK": 10
}
```

只搜正文/标题，不搜媒体资源：

```json
{
  "query": "China claims Luzon",
  "topK": 10,
  "enableMedia": false
}
```

搜媒体 OCR/ASR/caption 更重的场景：

```json
{
  "query": "map of taiwan military bases",
  "topK": 20,
  "enableKeyword": true,
  "enableSemantic": true,
  "enableMedia": true,
  "targetModalities": "image"
}
```

## 5. 响应字段说明

### 5.1 顶层 `data`

| 字段 | 类型 | 说明 |
|---|---:|---|
| `query` | string | 本次查询原文。 |
| `total` | integer | 本次返回命中数。注意是过滤后返回数，不是全库总命中数。 |
| `durationMs` | integer | 后端检索耗时，毫秒。 |
| `hits` | array | 贴文命中列表，按融合排序降序排列。 |

### 5.2 `hits[]`

| 字段 | 类型 | 说明 |
|---|---:|---|
| `contentId` | string | 后端 `media_contents.id`，UUID。 |
| `platform` | string | 平台。 |
| `contentType` | string | 内容类型。 |
| `platformContentId` | string | 平台原始内容 ID。 |
| `authorPlatformUserId` | string | 作者平台原始用户 ID。 |
| `title` | string | 标题，社交评论可能为空。 |
| `bodyText` | string | 正文。 |
| `language` | string | 内容语言。 |
| `publishedAt` | string | 发布时间。 |
| `url` | string | 原始 URL。 |
| `hashtags` | array | 话题标签。 |
| `mentions` | array | 原始 mentions 字段中的账号标识。 |
| `likeCount/commentCount/shareCount/repostCount/quoteCount/viewCount/reactionCount` | number | 互动指标。 |
| `rankScore` | number | 后端最终排序分，主要用于排序，不建议跨请求比较。 |
| `rrfScore` | number | RRF 融合分。 |
| `matchLevel` | string | 文本匹配等级，如 `EXACT_PHRASE`、`HIGH_TEXT_MATCH`、`TEXT_MATCH`、`HYBRID_RELEVANT`。 |
| `dominantHitType` | string | 主导命中类型，常见 `TEXT`、`MEDIA`、`TEXT_MEDIA`。 |
| `displaySuggestion` | string | 展示建议，提示优先展示正文还是媒体证据。 |
| `keywordScore` | number | ES 关键词原始相关性分数；仅关键词通道命中时有值。 |
| `semanticScore` | number | Milvus 语义相似度；仅语义通道命中时有值。 |
| `fusionScore` | number | 当前结果的融合排序分。 |
| `highlights` | object | ES 高亮片段，key 是字段名。片段里可能包含 `<em class="highlight">`。 |
| `primaryAsset` | object | 最主要的媒体命中资源；无媒体命中时为空。 |
| `matchedAssets` | array | 命中的媒体资源列表，如图片、视频、音频片段。 |
| `evidences` | array | 命中证据，说明结果来自哪个检索通道。 |

### 5.3 `evidences[]`

| 字段 | 类型 | 说明 |
|---|---:|---|
| `channel` | string | 命中通道，如 `ES_POST_KEYWORD`、`MILVUS_POST_SEMANTIC`、`ES_MEDIA_KEYWORD`、`MILVUS_MEDIA_SEMANTIC`。 |
| `category` | string | `TEXT` 或 `MEDIA`。 |
| `rank` | integer | 该通道内原始排名。 |
| `rrfContribution` | number | 该通道对融合分的贡献。 |
| `rawScore` | number | 通道原始分数。 |
| `hitField` | string | 命中字段，如 `body_text`、`ocr_text`、`asr_embedding`。 |
| `contentId` | string | 命中的内容 ID。 |
| `assetId` | string | 命中的媒体资源 ID；文本命中时为空。 |
| `entityId` | string | 内部检索实体 ID；通常算法侧可忽略。 |

## 6. 检索语义说明

### 6.1 关键词 vs 语义

- `enableKeyword=true`：适合精确短语、专名、明显关键词。
- `enableSemantic=true`：适合同义表达、跨语种表达、描述性 query。
- 推荐默认两个都开，由后端做融合排序。

### 6.2 跨语种检索

后端会对 query 做翻译扩展，并同时检索原文字段、翻译字段和 pivot 向量。

注意：

- 如果传 `language=en`，结果会限制为英文内容；这会提升精度，但可能降低跨语种召回。
- 如果希望最大召回，不要传 `language`。

### 6.3 多媒体资源检索

`enableMedia=true` 时，后端会把媒体命中聚合回对应贴文：

- 图片：OCR、caption、视觉语义。
- 视频：ASR、OCR、caption、关键帧语义。
- 音频：ASR 及其语义。

最终接口仍返回贴文列表，媒体证据放在 `matchedAssets/evidences`。

### 6.4 基础过滤

`platform`、`language` 会尽量下推到 ES/Milvus 检索阶段。

`contentType`、`authorPlatformUserId`、`publishedFrom`、`publishedTo` 当前在结果层过滤。为减少过滤后结果不足，后端会自动放大内部召回数量。

---

## 7. 调用建议

1. 默认调用建议：`enableKeyword=true`、`enableSemantic=true`、`enableMedia=true`。
2. 精确搜某句话：保留 `enableKeyword=true`，可同时开语义。
3. 查询很短且是专名：不要把 `semanticMinScore` 调太低，避免语义误召回。
4. 需要跨语种最大召回：不要传 `language`。
5. 需要严格某平台或某作者：传 `platform` 或 `authorPlatformUserId`。
6. 算法侧不要依赖 `rankScore` 的绝对值，只使用列表顺序和同一次请求内的相对大小。
